ListingAudit - EU Compliance Agent for Online Shop Listings

A multimodal AI agent that audits online shop listings against EU consumer and product-safety rules, cites the law behind every possible problem, and has a person approve each finding before anything reaches the seller.

🎯 What This Project Does

Online shops in the EU must show honest discounts (the 30-day price rule of the Omnibus Directive), manufacturer and safety information (GPSR), unit prices, textile fibre labels and energy labels. Marketplaces have millions of listings and few people to check them. ListingAudit does the first pass:

  • 💶 Honest Discounts - Checks every "was" price against 90 days of price history
  • 🏷️ Required Information - Manufacturer, responsible person in the EU, safety warnings, unit prices, fibre labels and energy labels
  • 🖼️ Photo Check - Spots photos that don't match the listing, with CLIP first and a vision model when CLIP is unsure
  • 📚 The Law Behind Each Finding - Searches a rulebook of nine EU and German law texts and cites the article
  • 🙋 Human in the Loop - A reviewer approves or rejects every finding; messages to sellers are drafted, never sent automatically
  • 📊 Measured, Not Guessed - Evaluated on 400 unseen listings against two simpler systems

A reviewer starts an audit on the review screen. The API runs the agent, which reads the listing and runs the checks through the toolbox. Plain code does every check it can; the language model only decides what code can't settle: the kind of product, the law behind each possible problem, and the wording of the findings. Code then checks the model's draft before anyone sees it, and the report waits in PostgreSQL until a person approves or rejects each finding.

📊 Results

The agent was compared with two simpler systems on 400 synthetic exam listings that nothing was tuned on: rules only (plain code, no AI) and one big prompt (the listing, its price history, its photo and the rules in one request to the model, no tools).

Question Agent Rules only One big prompt
Price problems caught 100% 100% 100%
Missing information and label problems caught 92% 92% 97%
Swapped photos caught 77% 0% 100%
Clean listings with a false alarm 5% 0% 58%
Flagged problems that are real (precision) 93% 97% 51%
Reports with only real numbers 100% 100% 67%
Clarity / fairness, judged by a model (1 to 5) 4.33 / 4.75 n/a 1.88 / 2.24
Cost per 1,000 listings $3.16 $0 $2.34

Takeaway: one big prompt catches slightly more, but half of what it flags is wrong and a third of its reports contain made-up numbers. The agent keeps false alarms at 5% with 93% precision, and every number in its reports comes from a check. Rules only can't see photos at all.

Next to improve: only 36% of the agent's findings quote the exact article of the rule's own law, and 67% of its suggested fixes pass the check once applied.

🚀 How to Use

You need Docker Desktop and uv. The agent also needs a gpt-5-mini deployment on Azure OpenAI; the repository's README shows how to set it up.

Set Up

BASH 
git clone https://github.com/aishwaryaj7/listingaudit.git
cd listingaudit
cp .env.example .env
uv sync
docker compose up -d

Build the Data

Loads the Amazon Berkeley Objects catalogue, builds the synthetic marketplace with its planted problems, and builds the searchable rulebook:

BASH 
uv run python -m listingaudit.data.download_abo
uv run python -m listingaudit.data.load_abo
uv run python -m listingaudit.data.download_images --per-type 100
uv run python -m listingaudit.market.build
uv run python -m listingaudit.rulebook.build

Audit and Review

Audit one listing in the terminal, or start the review API and, in a second terminal, the review screen:

BASH 
uv run python -m listingaudit.agent.run P0171
uv run uvicorn listingaudit.review.api:app
uv run streamlit run src/listingaudit/review/screen.py

Check the Results

Grade the saved evaluation against the answer key. This needs neither the database nor a model:

BASH 
uv run python -m listingaudit.eval.grade

🔧 Key Features

  • Plain Code First: the 30-day price rule, unit prices (including multipacks such as "3 x 250 ml"), fibre compositions and required product information are checked in code, each with a typed result and the articles of law it applies
  • Self-Check Before Review: every price and percentage in a report must come from a check, every quote from the law texts the search returned, and no draft may give a legal verdict; a failed draft goes back to the model with feedback
  • Safe With Seller Text: seller text reaches the model only as data, and no note in a listing can take a problem out of the report
  • MCP Toolbox: five read-only tools, the rules checklist, the law texts and the listing photos, offered to any MCP client
  • Rulebook Search: nine law texts cut into 542 chunks that keep their article numbers; meaning search with multilingual-e5 and pgvector finds a right article in the top five for 84% of test questions, against 45% for keyword search
  • Human Review That Survives a Restart: the agent pauses after its report and keeps its state in PostgreSQL; the API streams each step as server-sent events, and every decision goes to an audit log that only takes new rows
  • A Test Marketplace With a Hidden Answer Key: 800 real products with 90 days of prices, planted rule breaks in an easy and a hard version, and legal look-alikes as traps; the agent's database login can't read the answer key
  • Evaluation, Tracing and CI: a grader against the answer key, a DeepEval G-Eval judge for clarity and fairness, Langfuse traces for every audit, and GitHub Actions that fail the build on a made-up number
  • Cloud Deployment: a Docker image with CPU-only PyTorch and the models built in, deployed to Azure Container Apps with PostgreSQL, Blob Storage and Key Vault, described in Bicep, with managed identities instead of keys
